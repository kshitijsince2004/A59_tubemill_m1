# ZEDRAL — Furnace M1 Operator Console
# Cursor Implementation Prompt — Manual / Auto-From-Order Phase

## 0. OBJECTIVE

Implement the **Furnace / Annealing Furnace operator module** in the CURRENT Furnace codebase.

There are multiple physical Roller Hearth Furnaces:

- `RHF-03`
- `RHF-04`
- `RHF-05`

The operator workflow should be similar in usability to the existing Annealing console, but the ANN application is a **different codebase**.

### Critical cross-codebase rule

The existing ANN codebase is **REFERENCE ONLY**.

Do not:

- import ANN source code
- add ANN as a dependency
- assume ANN routes exist
- assume ANN database tables exist
- copy ANN-specific charge/base logic
- modify the ANN codebase
- make the Furnace repository depend on the ANN repository

Use the ANN specification only to understand the desired operator experience.

Implement Furnace using the architecture, framework, database conventions, routing, components and patterns that already exist in the CURRENT Furnace repository.

---

# 1. CURRENT PHASE — NO PLC / SCADA CONNECTION

This implementation phase is intentionally **NOT connecting to the furnace PLC, SCADA or historian**.

Do not implement:

- Siemens S7 communication
- OPC UA
- Snap7
- KEPServer
- WinCC historian integration
- PLC polling
- SCADA polling
- PLC tag mapping
- automatic live zone-temperature collection

The uploaded Furnace mapping identifies the furnace SCADA/PLC values as future AUTO sources, but that integration is deferred.

For this phase:

```text
PLC / SCADA = NOT CONNECTED
```

The system must nevertheless be architected so PLC/SCADA can be added later without redesigning the Furnace data model or UI.

---

# 2. WHAT "AUTO" MEANS IN THIS PHASE

There are two different meanings of automatic data.

## A. Auto-derived / system-filled

These values can be populated automatically NOW from the application/order/master data:

```text
Date
Shift
S No.
Furnace
Customer
OD × THK × Length
Work Order / PO No.
Specification / Grade
Heat Treatment
Total MT
```

depending on the available current repository/order data.

## B. Machine AUTO

These are identified as AUTO in the mapping but require PLC/SCADA/historian integration:

```text
Zone I–VI temperatures
Line speed
some metered gas consumption
```

These MUST NOT be treated as live AUTO values in this phase.

Instead:

```text
Current phase:
Machine fields = MANUAL INPUT

Future phase:
Machine fields = PLC/SCADA AUTO
```

This distinction is mandatory.
